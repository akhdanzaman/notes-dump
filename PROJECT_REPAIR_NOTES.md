# Arkaiv Spreadsheet Repair Notes

This project revision implements the spreadsheet audit's P0-P2 recommendations while keeping ambiguous records for review instead of guessing or silently deleting them.

## Sync integrity

- Physical sheet indexes retain every row occurrence for an ID.
- Duplicate multiplicity, row counts, unexpected/missing IDs, and row signatures are checked before and after writes.
- Canonical rewrites clear the complete prior managed range before writing current rows.
- Moves and deletes remove every old physical occurrence, bottom-up.
- Overview and Data Quality are refreshed during routine saves.
- Full JSON snapshot/history storage remains disabled in the active workbook to avoid recreating the audit's shared-string bloat.

## Persistence validation

- Same-ID duplicates are resolved deterministically; different-ID semantic matches remain visible as review candidates.
- Normal transactions require a positive amount and a valid source wallet.
- Wallet references are matched case-insensitively and normalized to registered IDs.
- Destination wallets are accepted only for transfer-like flows and must differ from the source wallet.
- Overlong structured values, JSON/instruction text, and model-style prose are rejected from production fields and retained only in bounded quarantine metadata.
- Validation now runs at Gemini Pro, legacy parser, local finance parser, and spreadsheet persistence boundaries.

## User export

- The old HTML document disguised as `.xls` was replaced with a genuine `.xlsx` workbook generated by ExcelJS.
- The export contains compact user-facing sheets and omits raw snapshots, histories, backups, configuration, and other technical tabs.
- Dates, numbers, and booleans are written as typed values, with tables, filters, frozen headers, bounded column widths, Rupiah/date formats, validation, wrapping, and conditional formatting.
- Export generation is lazy-loaded; the Control Center waits for completion and displays busy/error states.

## Compact Google Sheets presentation

- Save/sync keeps the complete round-trip schema, but shows only the most useful working columns by default; internal IDs, canonical fields, recurrence payloads, and parser metadata remain available as hidden columns.
- User-facing tabs now receive a frozen header, filter, compact widths, wrapping, Rupiah formats, dropdown guidance, alternating row shading, status colors, and missing/invalid-value highlighting.
- Dashboard and Data Quality stay first, followed by daily working tabs and editable configuration tabs.
- App state, history, chat history, canonical rules, and event log tabs are hidden from the normal workspace without being deleted.
- A sheet-level presentation-version marker applies the migration once to existing spreadsheets and avoids repeating large formatting batches on every save.
- Before any canonical clear/rewrite, the save pipeline now expands Google Sheets grid capacity when generated rows exceed 1,000 or schemas exceed 26 columns, with headroom for subsequent saves.
- Save verification trims presentation-only trailing rows and ignores locale-parsed chart-helper cells on `Sheet1`, while retaining strict ID multiplicity and full row-signature checks for every source-of-truth sheet.
